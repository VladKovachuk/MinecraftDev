# Правила разработки SmokeMod

## Использование папки AI

1. Не читать файлы в папке `AI` автоматически перед каждой задачей.
2. Читать файлы в папке `AI` только тогда, когда пользователь прямо попросил их прочитать или использовать.
3. Не обновлять, не дополнять и не переписывать файлы в папке `AI` после выполненных изменений, если пользователь прямо не попросил обновить документацию.

## Общие правила

1. Проект рассчитан на Minecraft 1.20.1, Fabric Loader и Java 17.

## Регистрация контента

- Новый предмет требует регистрации в `Registries.ITEM`, добавления в creative tab, item model, текстуры и локализации.
- Новый блок требует регистрации блока и BlockItem, blockstate, block model, item model, loot table и локализации.
- Внутренний ID не обязан совпадать с отображаемым именем, но это различие нужно документировать только по прямому указанию пользователя обновить документацию.

## Сушильный стол

- Рабочие слоты листьев находятся в индексах 1–9; индекс 0 зарезервирован и не отображается в текущем GUI.
- В одном рабочем слоте должен находиться максимум один лист.
- Shift-click должен распределять предметы по одному и уменьшать исходный стак только на число успешно заполненных слотов.
- Если перенос не состоялся, `quickMove` должен вернуть `ItemStack.EMPTY`.
- Сушка выполняется на сервере, а прогресс передаётся через `PropertyDelegate`.
- Видимые предметы требуют NBT-синхронизации BlockEntity и вызова обновления после изменения.
- Текущий GUI использует исходную текстуру 891×1001, масштабированную до панели 176×200.
- Координаты кликабельных слотов задаются в `DryingTableScreenHandler`, а фон и процент — в `DryingTableScreen`.

## Шейдеры

- `ShaderManager` загружает post-effect JSON из namespace `smokemod`.
- Сервер задаёт целевые значения эффектов, клиент плавно интерполирует отображаемые значения.
- После смерти визуальный эффект должен сбрасываться сразу.
