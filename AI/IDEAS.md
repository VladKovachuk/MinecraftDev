# Идеи и рекомендации для SmokeMod

## Игровое развитие

- Построить полную цепочку производства: семена → зелёный лист → сушёный лист → Shredded Tobacco → сигарета.
- Добавить рецепт сигареты с фильтром, где отдельный предмет фильтра влияет на результат.
- Добавить сигары, трубку, самокрутки и разные сорта табака.
- Добавить уровни зависимости, ломку и постепенное изменение переносимости никотина.
- Сбалансировать кратковременные положительные эффекты и долгосрочные отрицательные последствия.
- Добавить редкие семена или табачные изделия в сундуки структур.
- Добавить торговца или отдельную профессию жителя для табачных товаров.
- Добавить заменители табака с другими эффектами.
- Скрывать HUD при нулевом значении или сделать его поведение настраиваемым.

## Визуальные эффекты

- Добавить размытие, искажение изображения и лёгкое покачивание камеры.
- Поддержать сочетание нескольких эффектов без создания конфликтующих post-effect цепочек.
- Для каждого эффекта разделять серверное целевое значение и плавное клиентское отображение.
- Все имена shader program делать уникальными с префиксом `smokemod_`.

## Сушильный стол

- Вынести преобразования в отдельный реестр рецептов сушильного стола вместо жёсткой проверки одного предмета.
- При необходимости добавить поддержку автоматизации через воронки и чётко определить доступные стороны.
- Сохранять один предмет в одном слоте, чтобы внешний вид поверхности соответствовал сетке 3×3.
- При изменении GUI сначала измерять координаты слотов на итоговой масштабированной панели, затем обновлять ScreenHandler.
- Не менять инвентарь только на клиенте: все преобразования должны выполняться серверным BlockEntity.

## Технические рекомендации

- Все балансные числа вынести в конфигурацию: время сушки, шанс семян, скорость никотина и интенсивность эффектов.
- Для новых предметов проверять полный набор: регистрация Java, creative tab, модель, текстура и локализация.
- Для BlockEntity всегда синхронизировать NBT через initial chunk data и update packet, если состояние видно в мире.
- После изменения инвентаря вызывать обновление BlockEntity, чтобы клиентский рендерер сразу получал новое состояние.
- В `quickMove` уменьшать исходный стак только на реально перенесённое количество.
- Добавить небольшие диагностические команды для проверки стадий культуры, сушки и shader uniform.
- Проверить работу со вторым игроком до расширения механик автоматизации.
